# 前端重写：架构与约定

> 技术栈：Vite 8 + React 19 + TypeScript 5.9 + Tailwind v4 + Radix（shadcn 风格）
> + TanStack Query + react-router 7。Capacitor 打 APK/iOS。
>
> **不用 Next.js**：它唯一能帮上忙的是分享页 og:image，而那本来就由后端服务端渲染。
> 为一个功能引入和 Capacitor 打架的构建体系（静态导出会关掉 SSR）不划算。

## 一、目录

```
frontend/src/
├── main.tsx            唯一入口（旧前端有 8 个，已合并成按路由懒加载）
├── app/                外壳：只出现一次的东西
│   ├── App.tsx
│   ├── providers.tsx   Query / Toast / Confirm / Auth
│   ├── router.tsx      路由表（唯一）
│   ├── routes.ts       FRONTEND_TOP_SEGMENTS —— 路由冲突检查读它
│   └── layouts/        AppShell（登录后）· PublicLayout（公开页）
├── shared/             公共层：跨模块复用的一切
│   ├── config/         env.ts（唯一读 import.meta.env 的地方）· paths.ts
│   ├── api/            client.ts · errors.ts · queryClient.ts
│   ├── auth/           AuthProvider · guards · api · tokenStore · types
│   ├── lib/            cn.ts
│   ├── ui/             13 个公共组件（见下）
│   └── styles/         globals.css（设计令牌）
└── features/           业务模块，一个模块一个目录
    └── <模块>/
        ├── api.ts      该模块的后端调用（**只有这里知道接口长什么样**）
        ├── types.ts
        ├── components/ 该模块内部复用的组件
        └── routes/     页面
```

**判断某个东西该放 shared 还是 features**：被两个以上模块用 → shared；
只有一个模块用 → 留在那个模块里。不确定就先放模块里，第二个人要用时再提。

## 二、UI 分区（只有三层，不要发明新的）

| 层 | 是什么 | 谁负责 |
|---|---|---|
| 外壳 `AppShell` | 顶栏、导航、全局提示 | 整个应用一份 |
| 页面 `routes/*.tsx` | 一条路由一个页面，负责取数和编排 | 每条路由一份 |
| 分区 `<Card>` | 页面内的内容块 | 页面内若干份 |

每个页面的第一个元素是 `<PageHeader title description actions>`。
统一的标题层级是「UI 分区」最便宜也最有效的一半。

## 三、公共 UI（`@/shared/ui`）

`Badge` `Button` `Card`(+Header/Title/Description/Content/Footer) `Dialog`(+一套)
`Input` `Label` `PageHeader` `Select` `Skeleton` `Table`(+一套) `Textarea`
`LoadingState` `EmptyState` `ErrorState` `useToast` `useConfirm`

一律从 `@/shared/ui` 导入，不要深链到具体文件。

**三态不要自己写**：`LoadingState` / `EmptyState` / `ErrorState`。
旧前端每个页面各写各的，于是同一个"加载中"在不同页面长得不一样、
错误提示有的显示技术细节有的一片空白。

## 四、样式

- 颜色/圆角/字体全部来自 `globals.css` 的 `@theme` 令牌。
- **组件里不许出现具体色值**（`bg-[#0f766e]` 这种）。需要新颜色就去加令牌。
- 深色模式由令牌层负责（`prefers-color-scheme` + `[data-theme]`），组件不用管。
- 输入类控件字号必须 ≥16px（`text-base`）—— iOS Safari 会自动放大页面且缩不回去。
- 触控目标不小于 40px（`Button` 默认 `h-10`）。
- 顶栏加 `pt-[env(safe-area-inset-top)]`、底部加 `pb-[env(safe-area-inset-bottom)]`，
  否则 APK 全屏时被刘海和底部横条盖住。

## 五、数据

- **所有后端请求走 `@/shared/api/client` 的 `http`**，没有例外。
  绕过它就绕过了前缀、凭证和 401 处理，症状是「本地好好的，部署就 404」
  或者「会话过期后一直转圈」。
- 服务端状态用 TanStack Query，不要 `useState + useEffect` 手搓。
- 非 2xx 一律抛 `ApiError`，`error.message` 已经是后端的中文文案。
- 401 会由 client 广播给 `AuthProvider`，会话归零、守卫送去登录页 ——
  **各页面不要再自己判断 401**。

## 六、路由

- 网页用**路径路由**，APK 用 hash（构建时由 `VITE_ROUTER` 切换）。
  壳里没有服务端做 `try_files` 兜底，路径路由一刷新就白屏。
- ★ **前端路由的第一段不能和后端 38 个顶层路径重名**。nginx 把 `{BASE}/*` 全给后端，
  后端匹配不到才兜底发 SPA —— 重名的那条前端路由永远到不了浏览器。
  新增路由要同步 `src/app/routes.ts` 的 `FRONTEND_TOP_SEGMENTS`，
  `npm run build` 会先跑 `scripts/check-route-collisions.mjs` 拦这件事。
  已有先例：旧 `/info` 与后端 `/info/*` 撞车 → 前端改 `/about`。
- 页面一律 `lazy()`。

## 七、后端契约

- 路径是扁平的 `{BASE}/{资源}`，**没有 `/api` 段，也没有 `/v1`**。
- 响应信封只有一套：成功是业务 JSON，失败是 `{"status":"error","message":"中文"}`。
- 权限清单是后端代码里的常量（`backend/core/permissions.py`），不是库里的行。
