# 02 · Flask 与 FastAPI 的落差，以及本项目会踩的坑

逐项对照。**"本项目影响"一栏才是重点** —— 通用教程不会告诉你这些。

## 1. 同步 vs 异步：最大的认知陷阱

FastAPI 的性能优势来自 async I/O。但本项目的重活是：

- `subprocess` 31 处（ffmpeg 转码、pytesseract OCR、WeasyPrint/pdf2image 出 PDF）
- pymysql（**同步**驱动）+ SQLAlchemy 同步 session，2,500+ 调用点
- requests（同步 HTTP）调 BytePlus / Cloudflare / Resend

**这些全是阻塞调用。** 写成 `async def` 会直接卡死事件循环，整个进程所有请求一起挂。

正确做法：迁移后**绝大多数路由继续写 `def`（同步）**，FastAPI 会自动丢进线程池跑。
这意味着：

> **对纯 REST 而言，迁到 FastAPI 不会让这个项目变快。** 同步路由在线程池里跑，
> 吞吐和 gunicorn 同步 worker 是一个量级。**但长连接（SSE）是另一回事** ——
> 那正是本次迁移的动机，见 [03](03-迁移策略.md) §1。想要性能收益得把 pymysql 换 aiomysql、SQLAlchemy 换 async session ——
> 那是另一个数量级的工程（2,500 个调用点全改），本计划**不含**这一项。

真正的收益是：类型化请求校验、自动 OpenAPI 文档、依赖注入、更现代的中间件模型。
这些是**可维护性**收益；真正的性能收益在 SSE 长连接上。

## 2. ORM 会话生命周期

| | Flask | FastAPI |
|---|---|---|
| 会话作用域 | Flask-SQLAlchemy 绑定 app context，请求结束自动 `remove()` | 无内建，需自己做 |
| 模型基类 | `db.Model`，自带 `.query` | 裸 `DeclarativeBase`，**没有** `.query` |
| 404 助手 | `get_or_404` | 无 |

**本项目影响**：517 处 `.query.`、83 处 `get_or_404` 会直接 `AttributeError`。
解决方案是垫片而不是改代码，见 [04-兼容层设计.md](04-兼容层设计.md) §1。

⚠️ **线程池 + scoped_session 的坑**：同步路由跑在线程池里，`scoped_session` 默认按线程
分作用域 —— 线程复用会导致会话串场（A 请求没提交的数据被 B 请求看见）。
必须用 `scoped_session(..., scopefunc=<每请求唯一的 token>)` 并在中间件里 `remove()`。
这是整个迁移**最容易埋雷**的一处，务必按 04 文档的写法做。

## 3. 认证

| | Flask-Login | FastAPI |
|---|---|---|
| 当前用户 | 全局代理 `current_user`（线程局部） | 依赖注入 `Depends(get_current_user)` |
| 守卫 | `@login_required` 装饰器 | 依赖或中间件 |
| 会话 | 签名 Cookie（itsdangerous） | 无内建 |

**本项目影响**：
- 341 处 `current_user` 散落在 33 个非路由文件里。用 `ContextVar` 垫片可以原样保留，
  见 [04](04-兼容层设计.md) §2。
- **Cookie 必须逐字兼容**：Flask 的会话 Cookie 用 `itsdangerous` 以 `SECRET_KEY` 签名、
  URL-safe base64 + zlib 压缩。迁移后若换成 JWT 或别的方案，**所有已登录用户和所有
  APK 用户当场掉线**。必须自己实现同格式的读写，或继续用 `itsdangerous`。
- Bearer token 那条路（`request_loader`）比较独立，照搬 `session_service` 即可。

## 4. Socket.IO：本次全面下线

| | 现状 | 迁移后 |
|---|---|---|
| 服务端 | Flask-SocketIO + eventlet，独立进程 :8000 | **删除**，进程从 2 个变 1 个 |
| 客户端 | `socket.io-client`（21 个文件） | **删除**，改 `EventSource` + POST |
| 消息通道 | Redis message queue | **保留**，改成 Redis pub/sub 给 SSE 扇出 |

35 个事件里 22 个是客户端→服务器，SSE 替代不了，必须改成 POST。
完整设计见 [12-SSE改造方案.md](12-SSE改造方案.md)。

⚠️ 本项目下 eventlet 猴子补丁与 Python 新版本的兼容性在持续恶化 ——
下线 socket.io 顺带清掉了这个长期技术债。

## 5. 请求/响应 API 的逐项差异

| Flask | FastAPI | 本项目出现次数 |
|---|---|---:|
| `request.get_json()` | `await request.json()` 或 Pydantic 模型 | 161 |
| `request.args.get(k)` | `request.query_params.get(k)` 或函数签名参数 | 94 |
| `request.form` | `await request.form()`（**async**） | 33 |
| `request.files` | `UploadFile = File(...)`（**async**） | 30 |
| `jsonify(d)` | `JSONResponse(d)` 或直接 return dict | 1,174 |
| `send_file(p)` | `FileResponse(p)` | 65 |
| `abort(404)` | `raise HTTPException(404)` | 32 |
| `make_response` | `Response(...)` | 5 |
| `redirect(url)` | `RedirectResponse(url)` | 7 |

⚠️ **同步路由里拿不到 form/files**：`await request.form()` 是异步的，而我们的路由是
`def`（同步）。两条出路：(a) 上传类路由写成 `async def` 再把重活丢 `run_in_threadpool`；
(b) 用 FastAPI 的 `UploadFile` 参数声明，框架帮你 await。**30 处上传 + 33 处表单都要
逐个人工处理**，是纯机械但不能批量 sed 的部分。

## 6. 容易被忽略的行为差异（会悄悄改变线上表现）

1. **错误响应体变了**：`abort(404)` 在 Flask 下返回 HTML 错误页；FastAPI 返回
   `{"detail": "Not Found"}`。前端多数只看 `response.ok`，但**分享页/公开页**的 404
   体验会变。32 处要逐个确认。
2. **尾斜杠**：Flask 默认 `strict_slashes=False` 行为是 `/foo` 与 `/foo/` 互相 308 跳转；
   FastAPI 的 `redirect_slashes` 语义略有不同。有 574 个路由，**必须做全量 URL 对拍**。
3. **`SERVER_NAME` / `url_root`**：反代下 Flask 靠 `X-Forwarded-*`；FastAPI 要显式加
   `ProxyHeadersMiddleware`，否则 `_absolute_url()` 拼出来的分享链接会变成 `http://127.0.0.1`。
4. **CORS**：现在是 `CORS(app, resources={r"/*": {"origins": "*"}}, supports_credentials=True)`
   —— `origins="*"` 配 `supports_credentials=True` 在规范上是非法组合，Flask-CORS 会
   回显请求 Origin 来兼容。FastAPI 的 `CORSMiddleware` 用 `allow_origins=["*"]` +
   `allow_credentials=True` 会**拒绝**（它严格按规范办）。必须改成 `allow_origin_regex`。
   **这条如果漏了，APK 和跨域页面会整片报错。**
5. **最大请求体**：Flask 的 `MAX_CONTENT_LENGTH` 自动返回 413；FastAPI/Starlette **没有**
   这个开关，要么靠 nginx，要么自己写中间件。
6. **静态文件**：Flask 的 `static_folder` 自动挂 `/static`；FastAPI 要显式
   `app.mount("/static", StaticFiles(...))`。
7. **模板**：`render_template(name, **ctx)` → `Jinja2Templates.TemplateResponse(name, {"request": request, **ctx})`
   —— **必须传 request**，17 个模板 22 处调用都要改。
