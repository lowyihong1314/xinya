# 07 · 测试与验收

> 仓库现在有 **0 个测试**，而这次是 574 个路由 + 35 个实时事件的**一次性重写**。
> 一步到位意味着**没有"搬完一个验一个"的机会** —— 验收必须在切换前一次性做完。

## 1. 对拍为什么不再适用

上一版计划的核心手段是"Flask 版与 FastAPI 版逐字节对拍"。现在不行了，因为：

- 实时通道整个换了形态（socket.io → SSE + POST），没有可比的旧行为
- 路径前缀变了（`{BASE}`）
- 错误响应从 HTML 变 JSON

**但对拍仍然对 REST 部分有效**，而且很便宜 —— 只要新旧两套同时能跑（dev 环境跑新栈、
生产跑旧栈），就能拿真实请求比对。所以策略是：

| 部分 | 验证手段 |
|---|---|
| REST 路由（574 条） | **路由清单对账 + 抽样对拍**（忽略已知差异） |
| 实时（SSE） | **人工走查 + 真机弱网测试**（没有旧行为可比） |
| 认证 / 会话 | **线上真实 Cookie 验证**（硬门槛） |
| DB 会话隔离 | **并发串场自动化测试**（硬门槛） |

## 2. 硬门槛（不通过不许切换）

### 门槛 1 ★ 并发串场测试

```
20 个并发请求，10 读 10 写，每个写入自己的标记值；
断言：每个响应读到的都是自己写的那份，无任何交叉。
```

验的是 [04](04-兼容层设计.md) §1 的 `scoped_session` + `scopefunc`。
失败表现是**"偶尔把 A 的数据写给 B"，线上极难发现**。必须自动化、必须每次改动后重跑。

### 门槛 2 ★ 线上真实 Cookie 认证

拿一个**线上真实用户的会话 Cookie**，直接打新栈的 `/api/user_control/get_user_data`，
必须返回同一个用户。Bearer token 同理。

### 门槛 3 ★ 路由清单对账

```bash
# 旧栈
python scripts/dump_routes_flask.py > /tmp/routes_old.txt
# 新栈
python scripts/dump_routes_fastapi.py > /tmp/routes_new.txt
diff <(normalize /tmp/routes_old.txt) <(normalize /tmp/routes_new.txt)
```

574 条路由**一条都不能漏**。确实要删的（如 socket 相关、双下划线怪路径）
必须逐条列进"故意删除"清单并说明原因。

### 门槛 4 ★ APK 版本门禁已生效且升级率达标

见 [03](03-迁移策略.md) §6。没有门禁就切换 = 老用户集体白屏。

## 4. 实时功能验收 → [12-SSE改造方案.md](12-SSE改造方案.md) §7

单列一节强调三条最容易漏的：

- [ ] **一个页面只开一条 SSE**（DevTools Network 过滤 `realtime` 核实）
- [ ] **多标签页不排队**（验 HTTP/2，协议列必须是 `h2`）
- [ ] **锁屏 10 分钟后自动重连并拉到最新状态**

## 5. 性能与容量

- [ ] SSE 100 并发连接：内存、CPU、Redis 连接数
- [ ] MySQL 连接数：`worker 数 × 线程池大小` vs `max_connections`（见 [09](09-待决事项.md) D5）
- [ ] 最长请求（视频转码 / 批量 PDF）不被 worker timeout 杀掉
- [ ] SSE 端点的 snapshot 查询耗时（会占线程池，必须快）

## 6. 自动化测试（最小集）

不追求覆盖率，只写这些：

- [ ] 认证三条路：Cookie / Bearer / 401 响应体形状
- [ ] 权限拒绝 403 响应体形状
- [ ] 路由清单快照（门槛 3，写成脚本）
