# 04 · 兼容层设计

整个迁移能不能做成，取决于这三层垫片。目标只有一个：

> **让 `models/` 和各模块的 `services.py` 一个字都不用改。**

2,500+ 个 `db.*` 调用点、341 个 `current_user` —— 手改是不可能完成的任务，
也没有测试能兜住。垫片是唯一现实路径。

## 1. `db` 垫片（替掉 Flask-SQLAlchemy）

底层已经是 SQLAlchemy 2.0.48，Flask-SQLAlchemy 只是包了一层「app context 绑定 +
`.query` + `get_or_404`」。我们自己实现同样的门面即可。

> 数据库此时已是 PostgreSQL（阶段 P0 先做完，见 [15](15-PostgreSQL迁移.md)），
> 垫片与方言无关。

### 需要提供的 API（按使用量排序）

`db.Column`(895) `db.session`(775) `Model.query`(517) `db.relationship`(174)
`db.ForeignKey`(154) `db.Model`(100) `get_or_404`(83) `db.func`(32) `db.backref`(19)
`db.Table`(7) `db.or_`(2) `paginate`(3) + 各种类型（`db.Integer` `db.String` `db.Text`
`db.DateTime` `db.Boolean` `db.Numeric` `db.Date` `db.Time` `db.Enum` `db.Float`…）

### 骨架

```python
# core/db.py
from contextvars import ContextVar
import sqlalchemy as sa
from sqlalchemy import orm
from sqlalchemy.orm import DeclarativeBase, scoped_session, sessionmaker

# 每个请求一个 token —— 线程池复用线程时不会串场（见 02 文档 §2 的坑）
_scope: ContextVar[str] = ContextVar("db_scope", default="global")

# ⚠️ PG 默认 max_connections=100，4 worker × (8+4) = 48，留余量（见 09 D11-1 / 15 §6）
engine = sa.create_engine(
    settings.sqlalchemy_uri, pool_size=8, max_overflow=4,
    pool_pre_ping=True, pool_recycle=280,
)
SessionLocal = sessionmaker(bind=engine, autoflush=False, expire_on_commit=False)
Session = scoped_session(SessionLocal, scopefunc=_scope.get)


class _QueryProperty:
    """让 Model.query 继续可用。"""
    def __get__(self, obj, cls):
        return Session.query(cls)


class Model(DeclarativeBase):
    query = _QueryProperty()

    @classmethod
    def get_or_404(cls, ident, description=None):
        row = Session.get(cls, ident)
        if row is None:
            from fastapi import HTTPException
            raise HTTPException(404, description or "Not Found")
        return row


class _DB:
    """把 sqlalchemy 的命名空间原样暴露成 db.*，再补 Flask-SQLAlchemy 的专有件。"""
    Model = Model
    session = Session
    Table = sa.Table
    Column = sa.Column
    ForeignKey = sa.ForeignKey
    relationship = staticmethod(orm.relationship)
    backref = staticmethod(orm.backref)
    func = sa.func
    and_ = staticmethod(sa.and_)
    or_ = staticmethod(sa.or_)

    def __getattr__(self, name):          # Integer/String/Text/DateTime/... 一网打尽
        return getattr(sa, name)


db = _DB()
```

`models/__init__.py` 只需把 `from flask_sqlalchemy import SQLAlchemy; db = SQLAlchemy()`
换成 `from core.db import db`，**其余 100 个模型类、2,500 个调用点全部不动。**

### 会话生命周期

```python
# 中间件：每个请求进来设一个唯一 scope，出去时 remove
@app.middleware("http")
async def db_session_scope(request, call_next):
    token = _scope.set(uuid4().hex)
    try:
        return await call_next(request)
    finally:
        Session.remove()      # 归还连接
        _scope.reset(token)
```

⚠️ **这段是整个迁移最危险的代码**，写错的后果是「A 用户看到 B 用户的数据」且不报错。
必须：
- 并发压测 + 对拍（同一 token 并发打 20 个请求，校验互不串）
- `expire_on_commit=False` 保持与 Flask-SQLAlchemy 行为一致（否则 commit 后读属性会
  重新查库，83 处 `get_or_404` 之后的用法会变慢甚至炸）

### `get_or_404` 的语义差异

Flask-SQLAlchemy 的 `get_or_404` 抛 werkzeug 的 `NotFound` → HTML 页面。
垫片里抛 `HTTPException` → JSON。**83 处调用的错误响应体会变**，
在 [07](07-测试与验收.md) 的对拍里要把这项列为"已知允许差异"并逐个确认前端不依赖 HTML。

### 一次性切换，不存在双栈共存

因为不保留任何 Flask，垫片从第一天起就是**唯一**的 DB 门面 ——
不会出现"两套 session 写同一行"的事务打架问题。Flask 侧的 `db.init_app()` 直接删掉。

## 2. `current_user` 垫片（替掉 Flask-Login）

### 目标

341 处 `current_user.xxx`、168 处 `@login_required`、211 处 `permission_required(...)`
原样可用。

```python
# core/auth.py
from contextvars import ContextVar
from fastapi import Depends, HTTPException, Request

_current_user: ContextVar = ContextVar("current_user", default=None)


class _AnonymousUser:
    is_authenticated = False
    id = None
    username = None
    def __getattr__(self, name): return None


class _CurrentUserProxy:
    """代理到 ContextVar，让 341 处 current_user.xxx 原样工作。"""
    def __getattr__(self, name):
        return getattr(_current_user.get() or _AnonymousUser(), name)
    def __bool__(self):
        return bool(_current_user.get())


current_user = _CurrentUserProxy()


async def resolve_user(request: Request):
    """中间件调用：先认 Bearer，再认会话 Cookie。顺序与 flask_login 一致。"""
    user = _user_from_bearer(request) or _user_from_session_cookie(request)
    _current_user.set(user)
    return user
```

- `@login_required` → 保留同名装饰器，内部检查 `current_user.is_authenticated`，
  不通过就 `raise HTTPException(401, ...)`，**响应体要与现在的
  `{"status":"error","message":"unauthorized"}` 逐字一致**（`app/auth.py:71`）。
- `permission_required(name)` → 内部逻辑照抄现有实现，连 `print("[权限拒绝]", ...)`
  和 403 响应体都保持一致。

### 会话 Cookie 必须逐字兼容

Flask 的会话 Cookie 格式 = `itsdangerous.URLSafeTimedSerializer` +
`TaggedJSONSerializer` + zlib，密钥是 `SECRET_KEY`。
**继续用 `itsdangerous` 自己读写同格式**，不要换 JWT。验收标准：

> 拿一个**线上真实用户的 Cookie**，直接打 FastAPI 版 `/api/user_control/get_user_data`，
> 必须返回同一个用户。这条不通过，不许上线。

`REMEMBER_COOKIE_*`（记住我）同理，Flask-Login 的 remember cookie 是
`user_id|timestamp|hmac` 格式，也要照实现。

## 3. 响应垫片

统一一个 `json_response()`，保证 `{"status": ..., "message": ...}` 约定与
HTTP 状态码组合和现在完全一致：

```python
# core/responses.py
from fastapi.responses import JSONResponse

def jsonify(obj=None, /, **kwargs):
    """兼容 Flask 的 jsonify(dict) 与 jsonify(k=v) 两种调用。"""
    payload = obj if obj is not None else kwargs
    return JSONResponse(payload)
```

⚠️ Flask 路由里 `return jsonify(...), 403` 这种「元组带状态码」的写法很常见，
FastAPI 不认。搬迁时要改成 `JSONResponse(payload, status_code=403)`。
**这是机械但必须逐处处理的改写**，无法 sed（因为状态码位置多变）。

用量统计：`return jsonify(` 后跟逗号状态码的写法，搬每个模块前先数一遍。

## 4. 其他小垫片

| Flask | 垫片做法 |
|---|---|
| `send_file(path, as_attachment=True, download_name=...)` | 包一层 `FileResponse`，参数名映射 |
| `abort(404)` | `raise HTTPException(404)`；**注意响应体从 HTML 变 JSON** |
| `request.get_json(silent=True)` | 同步路由里用 `await` 不了 → 封装成依赖注入 `body: dict = Depends(json_body)` |
| `render_template(n, **ctx)` | 包一层自动塞 `request` 的 `TemplateResponse` |
| `current_app.config[...]` | 换成 `core.config.settings.xxx`（11 处，见 [10](10-配置中心.md)） |

## 5. 垫片是长期资产，不是临时脚手架

因为不保留 Flask，这些垫片切换当天就是正式实现：

- **长期保留**：`db` 垫片（本质是自己维护的 mini Flask-SQLAlchemy，替掉它意味着
  重写 2,500 个调用点，永远不划算）
- **长期保留**：`current_user` 代理（341 处）
- **切换后逐步淡出**：`jsonify` 元组垫片、`render_template` 垫片 ——
  新写的代码直接用 `JSONResponse` / `TemplateResponse`，老代码不动
- **新代码的方向**：新路由用 `Depends(get_current_user)` 而不是全局代理；
  老路由保持原样，不为统一风格去动它们
