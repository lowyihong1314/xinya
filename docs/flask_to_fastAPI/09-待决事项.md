## 仍需拍板

### D8 ★ SSE 的认证方式（影响 APK 架构，动手前必须定）

`EventSource` **不能自定义请求头**，带不了 `Authorization: Bearer`。三选一：

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. `?access_token=` 查询参数** | 改动最小 | token 会进 nginx access log（需配 log 脱敏）；URL 可能被截图/分享泄露 |
| **B. APK 改用 Cookie 认证** | 与网页端统一，最干净 | APK WebView 跨站 Cookie 配置要重验（`SameSite=None; Secure` 已在用，风险可控） |
| **C. `fetch` + `ReadableStream` 自己解析 SSE** | 能带头，最灵活 | 要自己实现重连、心跳、错误恢复，多写几百行且容易有边界 bug |

> **倾向 B**：现在 APK 本来就同时支持 Cookie 与 Bearer 两条路（`app/auth.py` 的
> `user_loader` + `request_loader`），把 SSE 统一走 Cookie 不增加新机制。
> 但需要先在真机 WebView 上验证长连接下 Cookie 能稳定携带。

### D10 路径命名（dev 已定，生产待定）

**已定**：开发环境 `APP_BASE_PATH=/UTBA_DEMO`。

`APP_BASE_PATH` 是 `system_config.env` 里的**每环境配置**，不是写死在代码里的常量 ——
所以 dev 叫 `/UTBA_DEMO` 不会把 "DEMO" 带进生产。

**余项：生产用什么？**（在阶段 B 上线前必须定）

⚠️ 两点风险，定生产值时请考虑：

1. **大小写敏感**。URL 路径区分大小写，`/UTBA_DEMO` 与 `/utba_demo` 是两个不同的地址。
   有人手打小写就是 404。缓解：nginx 加一条不区分大小写的重定向到规范写法 ——
   ```nginx
   location ~* ^/utba_demo(/.*)?$ { return 301 /UTBA_DEMO$1; }
   ```
   （规范写法只有一个，其余一律 301 过去，避免同一页面两个 URL。）
2. **下划线 + 大写不是 URL 惯例**。通行写法是小写加连字符（`/utba-demo`）。
   不影响功能，只影响观感与手打成功率 —— dev 环境无所谓，生产值建议再斟酌。
