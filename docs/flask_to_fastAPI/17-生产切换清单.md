# 生产切换清单

> dev 站（yukang.utbabuddha.com → 5102）已经全量跑 FastAPI。
> 生产站仍跑 Flask（`gunicorn wsgi:app :5006`，代码在 `/srv/flaskapp/xinya`，
> 是**另一份 checkout**，不受本分支影响）。
>
> 这份清单是把生产切过来要做的事。**顺序有讲究**，标了先后的别调换。

## 一、切换前必须先做

### 1. 代码部署（但不启动）

```bash
cd /srv/flaskapp/xinya
git fetch && git checkout xinya_v3
./venv/bin/pip install -r requirements.txt
```

⚠️ `xinya_v3` 里**没有 `wsgi.py`**（Flask 入口已删）。checkout 之后旧的
`xinya_flask.service` 会起不来 —— 这是预期的，但意味着**没有回退窗口**：
要能回退就先把当前 commit 记下来，回退是 `git checkout <旧 commit>`。

### 2. 数据库迁移

```bash
cd /srv/flaskapp/xinya && ./venv/bin/alembic upgrade head
```

当前 head 是 `ff4115af76ac`（伴奏 1 对 1 + 歌单排序 + 歌本↔音频）。
它带**一次性数据处理**：把库里已有的伴奏自动配对（dev 上配了 31 对）。
生产数据不同，配对数会不一样 —— migration 会打印配了几对。

### 3. 前端构建

```bash
cd /srv/flaskapp/xinya
scripts/gen_frontend_env.sh        # 从 system_config.env 生成 .env.production
cd frontend && npm ci && npm run build
```

产物落在 `static/vite/`。`npm run build` 会先跑路由冲突检查与权限名检查，
两者任一失败就不出产物 —— 这是有意的。

## 二、切换（这一步开始有停机）

### 4. systemd 单元

`xinya_flask.service` 改成 uvicorn：

```ini
ExecStart=/srv/flaskapp/xinya/venv/bin/gunicorn \
    -k uvicorn.workers.UvicornWorker -w 4 -b 0.0.0.0:5006 backend.main:app
```

⚠️ **worker 数与 PG 连接数**：4 worker × 每个自己的连接池。
`core/config.py` 的 `db_pool_size` / `db_max_overflow` 要乘以 4 之后
仍小于 PG 的 `max_connections`（默认 100，`scripts/setup_postgres.sh` 调到了 150）。

### 5. nginx

**(a) `/cctv_authz` —— 必改，否则监控要么全断要么全开**

`/etc/nginx/conf.d/flaskapp_http.conf:132` 现在是：

```nginx
proxy_pass http://127.0.0.1:5006/api/move_camera/authz;
```

v3 里 `/api` 段没有了，要改成：

```nginx
proxy_pass http://127.0.0.1:5006/move_camera/authz;
```

这条是 `auth_request`，nginx 靠它的**状态码**放行/拒绝视频流：
200 放行、401/403 拒绝。路径错了会得到 404 —— nginx 把非 2xx 一律当拒绝，
所以症状是「登录了也看不到画面」。
反过来如果哪天它意外回了 200，就是「没登录也能看」。
**改完必须用 `curl -I` 实测 200 / 401 / 403 三种情况。**

**(b) 静态资源前缀**

生产站如果不走 `/UTBA_DEMO` 前缀，`VITE_BASE_PATH` 要设成空，
否则 `static/vite/index.html` 里的资源路径会多一段。

**(c) SPA 兜底**

前端改成了**路径路由**（不再是 `#/`）。nginx 必须把匹配不到的路径转给应用 ——
应用里 `backend/api/web/` 的 catch-all 会发 SPA 外壳。
如果 nginx 有 `try_files` 直接发静态文件的 location，要确认它不会
把 `/events/219` 这类路径吃掉。

## 三、切换后立刻验

```bash
B=https://<生产域名>
curl -s -o /dev/null -w '%{http_code}\n' $B/            # SPA 外壳
curl -s -o /dev/null -w '%{http_code}\n' $B/ping        # 200 pong
curl -s -o /dev/null -w '%{http_code}\n' $B/members     # 401（**不是 200**）
curl -s $B/event/<某个活动id> | grep -c 'og:image'      # 分享页元信息 ≥1
curl -s -o /dev/null -w '%{http_code}\n' -I $B/favicon.ico   # HEAD 要 200
```

★ `/members` 必须是 401。切换前它是**完全不鉴权**的（匿名可拉 258 条含身份证号
的记录，见 commit aeeccdf），如果切换后还是 200 说明鉴权没生效。
