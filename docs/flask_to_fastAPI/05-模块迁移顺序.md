# 05 · 模块迁移顺序

排序原则：**先拿小而独立的练手验证垫片，再吃中等模块，最后啃 `fahui`。**
带模板/上传/子进程的排后面，纯 JSON CRUD 排前面。

> 形态是一次性重写（见 [03](03-迁移策略.md)），所以这里的"顺序"不是上线顺序，
> 而是**开发顺序**：每搬完一个就在 dev 域名上走查该模块的页面，不等到最后才验。

状态列在执行时更新：`⬜ 未开始` / `🟡 进行中` / `✅ 已上线` / `⏸ 暂缓`

## 依赖关系（会影响顺序的硬约束）

```
core/db 垫片 ─┬─→ 所有模块
core/auth  ──┘
                app/common/council_sign.py  ← form/ 与 fahui/ 共用，搬 form 前先处理
                app/media/services.py       ← event/ music/ filesystem/ 都调它
                app/form/permissions.py     ← form/ 与 fahui/ 共用
```

**共享 services 的处理办法**：它们里面用了 `request`/`current_user`（33 个文件）。
垫片生效后这些代码原样可用，所以**不需要提前重构** —— 但 `app/media/services.py`
被三个模块共用，搬第一个用到它的模块时就要把它纳入对拍范围。
