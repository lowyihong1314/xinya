## 三点五、已知的框架级行为差异

批次二的对抗式核验（5 模块 × 3 视角）报出 70 处，其中 5 类是**系统性**的
（跨 3–5 个模块，意味着批次一的 7 个模块同样中招）。三类已在框架层修掉，两类
评估后接受并记录在此。

### 已修（框架层，一处改动覆盖全部模块）

| 差异 | 修法 |
|---|---|
| 未登录 + 请求体不合法 → 422 而不是 401，前端的重新登录跳转不触发 | `core/auth.py` 的 `_make_wrapper` 把 guard 挂到包装函数上（`__xinya_auth_guard__`），`backend/main.py` 的 422 处理器从 `scope["endpoint"]` 取出来先跑一遍，补回「鉴权优先」。四种畸形 body 已复验全部回 401 |
| 尾斜杠 `/x/` 被 307 重定向（Flask 是 404），带副作用的 POST 会被浏览器重发 | `FastAPI(redirect_slashes=False)`。新旧两边都没有带尾斜杠的路由，纯粹是行为还原 |
| `get_or_404` 的 404 从 HTML 页变 JSON 后，用户看到英文 "Not Found" | `core/db.py` 默认文案改中文「未找到」；调用方传了自己的文案就用它的 |

### 接受并记录（触发面小，前端不会构造）

1. **重复查询参数取值方向相反**：`?q=a&q=b` 时 Flask 的 `request.args.get` 取
   **第一个**，Starlette 的 `QueryParams.get` 取**最后一个**。前端用
   `URLSearchParams` 不会造出重复键，只有手工或第三方调用会踩到。
   真要统一，用 `request.query_params.getlist(k)[0]`。

2. **没有 body / Content-Type 不是 json 时状态码不同**：Flask 的
   `request.get_json()`（无 `silent=True`）抛 **415**；`Optional[dict] = Body(None)`
   会落成 `None` → `payload or {}` → 走进业务分支返回 400/404。
   注意这会让一些**原本永远到不了**的分支变得可达，个别文案会显得答非所问
   （如 import_docx 回「docx 文件不存在」，实际原因是没发 body）。

### 不是差异（核验的误报）

13 处「高危」里有 11 处是「模块没注册到 `api/router.py`」—— 那是我刻意留给
统一接线的一步，不是搬迁错误。接线已完成。

## 四、开发约定

- 重启 dev 服务一律用 `./scripts/dev_server.sh restart`。
  **不要用 `pkill -f run.py`**——同机的 OCR_project / BearBad / sengchong 入口也叫 `run.py`，
  会被一起杀掉（已经误杀过一次，靠 systemd 自动拉起才没出事）。
- 搬模块的硬性约束（违反会启动即失败或线上事故）：
  1. 文件里不能写 `from __future__ import annotations`（core.auth 的装饰器用
     `functools.wraps` 包过，FastAPI 会去 `core/auth.py` 的命名空间求值注解，找不到 `Optional`）；
  2. 路由一律 `def` 不用 `async def`（底下是同步 DB/Redis 调用，会焊死事件循环）；
  3. 装饰器顺序：`@router.get(...)` 在上、`@login_required` 在下。
