### 3.2 认证：Flask-Login

| 用法 | 出现次数 |
|---|---:|
| `current_user` | 341 |
| `@login_required` | 168 |
| `permission_required(...)` | 211 |
| `flask_login` 导入 | 49 |

认证有**两条路**（`app/auth.py`）：
- `@login_manager.user_loader` → 会话 Cookie（网页端）
- `@login_manager.request_loader` → `Authorization: Bearer <token>`（APK，走 `app/mobile/session_service.py`）

权限模型：用户 → 部门（多对多）→ 部门权限名集合；权限清单硬编码在 `app/auth.py` 的
`permission_names` 里，不入库。

Cookie 配置（`app/settings.py`）：`SameSite=None` + `Secure` + 7 天有效期 —— 为了 APK WebView
从 `https://localhost` 跨站带 Cookie。**迁移后必须逐字保留，否则所有 APK 用户当场掉线。**

### 3.3 Flask 全局对象的渗透范围

`request` / `current_user` 出现在 **33 个非路由文件**里（services、permissions、socket_events…）。
也就是说业务层不是纯函数，不能直接搬 —— 要么一起改，要么用上下文垫片。

好消息：`flask.g` **实际没被使用**（15 处 `g.` 全是循环变量），`before_request` / `after_request` /
`errorhandler` **一个都没有注册**。钩子面干净。

## 4. 生产拓扑

```
                       ┌─ /socket.io/ ──────→ 127.0.0.1:8000
                       │                      gunicorn --worker-class eventlet -w 1
                       │                      socket_wsgi:app  (create_app(socket=True))
 nginx  ───────────────┤
 v2.utbabuddha.com     ├─ /media_file/ ─────→ 本地文件，miss 时回落 5006
 utbabuddha.com        │
 utba.my               ├─ /cctv_authz ──────→ 5006 的 /api/move_camera/authz（auth_request 内部鉴权）
                       │
                       └─ 其余全部 ─────────→ 127.0.0.1:5006
                                              gunicorn -w 4 wsgi:app  (create_app(socket=False))
                                              ↑ 同步 worker，无 socket
        Redis ── socket.io message queue + quiz/mirror 房间态 + 在线用户
        MySQL ── pymysql
```

关键结构：**HTTP 进程本身不跑 Socket.IO**，需要推消息时用 `socket_broker`（一个带 Redis
message_queue 的 SocketIO 客户端）把事件丢进 Redis，由 8000 端口那个进程广播。
→ 这是个天然的解耦缝，意味着 **HTTP 层可以独立迁移，Socket.IO 进程原样不动**。

systemd：`xinya_flask.service`（5006）、`xinya_socket.service`（8000），都在 `/srv/flaskapp/xinya`。

## 7. 路径基座现状（多项目部署的阻碍）

当前整套系统假设自己**独占域名根路径** `/`：

| 位置 | 硬编码 |
|---|---|
| `app/settings.py` | `API_PREFIX = "/api"` |
| `frontend/vite.config.js` | `base: "/static/vite/"` |
| `static/index.html` | `src="/static/vite/init.js"`、`href="/favicon.ico"` |
| `app/web.py` | `_absolute_url()` 用 `request.url_root` 拼分享链接、`redirect("/#/...")` 短链 |
| `app/common/council_sign.py` | `request.host_url` + `/template/council-sign` |
| 前端 41 处 | `window.location.origin + "/..."` 拼二维码、分享链接、下载兜底 |
| 前端 5+ 处 socket | `io(origin)`，默认连 `/socket.io/` |
| Cookie | `path` 默认 `/` |

→ 这正是 `VITE_BASE_PATH` 要解决的，见 [11-BASE_PATH.md](11-BASE_PATH.md)。
