# 转盘器设计稿（老虎机组乐团）

## 目标

在 `转盘 > 转盘活动` 里做一个老虎机风格的随机组乐团工具。

只在主持/电脑端使用，不需要游客端、Socket.IO、二维码。

核心体验：

- 进入后是一个老虎机 UI。
- 3-6 个槽位，每个槽位代表一个角色分类（如吉他手、钢琴手、歌手）。
- 每个槽位有自己的候选人池（后台配置）。
- 点击开始后，所有槽位滚动，每个槽位从自己的候选池里随机抽出一个人。
- 最终结果 = 每个槽位各一人 = 一个随机组成的小乐团。

## 页面结构

### 1. 老虎机主页

入口：`/music/turntable` 点击 `转盘活动` 后进入。

要求：

- 隐藏顶部 navbar。
- 左上角返回按钮，返回 `抢答活动 / 转盘活动` 两个大按钮页。
- 右上角 setting icon，进入配置界面。
- 主体是老虎机式结果区：
  - 3-6 个槽位横排显示。
  - 每个槽位上方显示角色名称（如「吉他手」「钢琴手」「歌手」）。
  - 未抽取时每个槽位显示大 `?`。
  - 抽取后显示抽中的用户头像和名字。
- 底部操作按钮：
  - `开始` — 所有槽位开始滚动抽取。
  - `重抽` — 清空当前结果，重新抽取。
  - `清空结果` — 清空显示，回到 `?` 状态。
- 显示状态：
  - 未配置（没有设置角色或候选人）
  - 准备抽取
  - 抽取中（滚动动画）
  - 已完成（显示乐团结果）
  - 候选人数不足（某个角色池为空）

### 2. 设置界面

从主页右上角 setting icon 进入。

配置项：

- **槽位数量**
  - 取值范围：3-6。
  - 对应主页显示几个老虎机槽位。
- **每个槽位的角色配置**
  - 角色名称（自定义，如「吉他手」「钢琴手」「歌手」「贝斯手」等）。
  - 角色候选人池：从用户列表中选择属于这个角色的用户。
  - 例如：槽位 1 = 吉他手们 [张三, 李四, 王五]；槽位 2 = 钢琴手们 [赵六, 孙七]；槽位 3 = 歌手们 [周八, 吴九, 郑十]。
- **抽中返回**
  - 开启：被抽中的人下一轮仍然留在候选池，可以再次被抽中。
  - 关闭：被抽中的人从候选池中移除，直到手动重置。
- 保存配置
  - 保存后返回主页，槽位数量和角色名称立即更新。
  - 如果槽位数量变化，清空当前结果。

## 抽取规则

定义：

- `slot_count`：槽位数量，3-6。
- `slots`：每个槽位的配置 `{ name: string, candidates: User[] }`。
- `return_after_drawn`：抽中返回开关。
- `used_ids_per_slot`：每个槽位已被抽中过的用户 ID（仅在 `return_after_drawn = false` 时使用）。

### 抽取流程

1. 检查每个槽位的可用候选人是否 >= 1，否则提示该角色候选人不足。
2. 每个槽位从自己的可用候选池中随机抽取 1 人。
3. 各槽位独立抽取，不互相影响（同一个用户可以同时被不同槽位抽中）。
4. 抽取完成后，如果 `return_after_drawn = false`，将被抽中的用户加入对应槽位的 `used_ids_per_slot`。

### 抽中返回 = 开启

- 每轮从该槽位的完整 `candidates` 中随机抽 1 人。
- 不同轮之间可以抽到同一个人。

### 抽中返回 = 关闭

- 每轮从 `candidates - used_ids_per_slot[slotIndex]` 中随机抽 1 人。
- 抽中后加入 `used_ids_per_slot[slotIndex]`。
- 当某个槽位可用候选人为 0 时，禁用开始并提示。
- 可手动「重置已使用名单」恢复所有槽位的候选池。

## UI 动画

老虎机风格，保持简单：

1. 点击 `开始`。
2. 状态变为 `抽取中`。
3. **先计算好最终结果**。
4. 每个槽位显示快速变化的候选用户名字/头像，持续 1-2 秒。
5. 槽位从左到右依次停止，显示最终抽中的人。
6. 全部停止后状态变为 `已完成`。

动画只影响显示，不影响最终结果。

## 数据结构草案

前期纯前端保存到 `localStorage`，不需要数据库。

```ts
type SlotUser = {
  id: number;
  username?: string | null;
  display_name?: string | null;
};

type SlotConfig = {
  name: string;           // 角色名称，如「吉他手」
  candidates: SlotUser[]; // 该角色的候选人池
};

type SlotMachineSettings = {
  slot_count: number;              // 3-6
  slots: SlotConfig[];             // 每个槽位的配置
  return_after_drawn: boolean;     // 抽中返回
};

type SlotMachineRoundResult = {
  created_at_ms: number;
  picks: SlotUser[];  // picks[i] = 第 i 个槽位抽中的人
};

type SlotMachineState = {
  settings: SlotMachineSettings;
  used_ids_per_slot: number[][];          // used_ids_per_slot[i] = 槽位 i 已抽中的用户 ID
  current_result: SlotMachineRoundResult | null;
};
```

localStorage key 建议：

```text
xinya.slotmachine.settings
xinya.slotmachine.usedIdsPerSlot
xinya.slotmachine.currentResult
```

## 实现阶段

### Phase 1：静态 UI

- 老虎机主页。
- 3-6 个槽位，大 `?` 默认状态，上方显示角色名称。
- setting icon。

### Phase 2：设置界面

- 槽位数量调整（3-6）。
- 每个槽位配置角色名称。
- 每个槽位选择候选人（读取 `/api/user_control/get_all_user_data`）。
- 抽中返回开关。
- 保存到 localStorage。

### Phase 3：随机抽取

- 每个槽位从自己的候选池独立抽取 1 人。
- 支持抽中返回 / 不返回。
- 支持重置已使用名单。

### Phase 4：老虎机动画

- 开始时先计算最终结果。
- 视觉滚动 1-2 秒。
- 槽位依次停止并显示结果。

### Phase 5：体验补强

- 显示历史回合（之前组成过的乐团）。
- 支持临时手动移除某个候选用户。
- 支持导出当前乐团结果。

## 明确不做

- 不做游客端。
- 不做 Socket.IO。
- 不做二维码。
- 不做后端抢占/实时同步。
- 第一版不需要数据库保存。
